# Reporting a vulnerability

The maintainers consider fixes for the latest experimental preview. Response times are best effort.

Use **Security → Advisories → Report a vulnerability** on GitHub. If that option is missing, open a public issue asking the maintainer to enable private reporting. Keep vulnerability details private.

In the private report, include the Co² build, Codex Desktop and OS versions, steps to reproduce with synthetic data, and the access you expected versus what happened. Omit live invitations, credentials, real conversations, authentication files, SQLite databases, session logs and diagnostic archives. Revoke any invitation or visitor credential you accidentally shared.

For guest permissions, encryption and revocation, see the [sharing boundaries](README.en.md#security-at-a-glance).
